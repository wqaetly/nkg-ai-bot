# 电脑配置顾问 Flow 4.7

## 当前流程

对话层联网检索 → 需求与用途 → 同平台主型号 → 后台商城核价 → 根据缺件/总预算发起新联网搜索 → 分析并核实替代型号 → 再次核价与重选组合 → 简洁商品清单。

联网信息随本轮请求交给规划节点，用于选择具体型号。Flow 不再逐部件重复搜索网页摘要价格，也不把摘要价格算作商城报价。每次更换型号前通过已有联网搜索服务获取新资料，结合当前报价、目标价和用途重新规划；不限于首轮的预设替代型号。用户关闭联网或搜索不可用时，停止替代规划并保留已核价结果，不能把规则回退型号描述为已由最新网页确认。

## 预算反馈

- 先覆盖所有目标部件，再判断整单贵或便宜；缺件小计不能用于升级预算判断。
- 完整报价超过预算时，优先查询价格占比高、用途权重低的部件的兼容降本型号。
- 完整报价低于预算的 90% 时，优先查询用途权重高的部件的兼容升级型号。对 8000 元预算，即低于 7200 元才主动升级；不会为了用满预算购买无益的外观升级。
- 每获得一个替代型号报价，都保留原候选并重新计算全局组合。优先在预算内最大化用途评分；升级报价超预算时保留原方案。一次变更不够时继续调整其他部件。
- 替代候选必须引用本轮真实搜索 URL，来源中需出现该型号及原插槽/内存代际证据；拒绝编造来源、重复查询、已知平台冲突与低于原计划容量下限的替代。单个替代无效时继续考虑其他部件，搜索整体不可用则明确停止。
- 候选来自逐轮联网规划；评分是用途优先级启发式，不是实时性能跑分，也不是无限搜索所有硬件的全局最优保证。
- 升级与降本的评分分开；报价相同、效用更低的方案不会覆盖已有方案。内存/存储升级按替代型号的目标容量核验，实际商品规格仍只来自商品证据。
- 每个槽位首次核价后最多两轮联网替代，每轮两个搜索词与一次模型分析。删除旧联盟流程的宽泛类目补搜、板 U 套装发现与二次确认分支。全程最多 32 次查询、约 8 分钟；每次查询最多核验四个详情。登录/验证失败、超时和次数限制不能被预算调整覆盖。

## 商城与窗口

支持拼多多、京东、淘宝（含天猫），通过 `COMPUTER_SHOPPING_PLATFORM` 选择。用户主动点击“商城登录”才打开可见窗口；搜索、详情采集均使用隐藏的系统 WebView，不抢焦点。

平台选择在打开登录窗口前保存。每个平台复用固定本机目录。正常关闭、退出和重启时，将会话 Cookie 持久化至 WebView2 加密存储；Windows 直接更新原生 Cookie 对象的有效期，保留原域/主机作用域，避开 Tauri/wry 经 cookie::Cookie::domain() 丢失前导点的转换路径；网站删除的 Cookie 不会由旧快照恢复。平台仍可能自行使登录失效。采价后台遇到真实登录或验证要求时停止并提示用户从商城登录入口处理。

采集器在导航前监听页面原有 JSON/JSONP 请求，结合 SSR 数据和商品卡片 DOM；随后访问同一商品 ID 的详情页。地址、物流、购物车、评论以及详情页推荐等辅助接口不参与商品可用性判断，单独的接口令牌错误不等价于用户掉线。真实登录页面、商品主接口会话失效与验证仍被保留。

参考 [ai-goofish-monitor 的采集流程](https://github.com/Usagi-org/ai-goofish-monitor/blob/77f8d75869acd65f9dba72731b95c7c49ea67bdf/src/scraper.py) 的先监听响应、明确结构解析、独立详情核验方式。没有引入其运行环境，也不重建商城私有接口签名。

## 价格与输出

- 只展示选中且有详情身份、正数价格和合法直链的商品。搜索卡片缺价可继续访问详情。
- 排除二手/拆机等负面匹配；多型号 CPU、多个主板芯片组、显卡混合显存/型号或内存混合频率共用一个展示价的商品不进入预算组合，避免把其他规格的低价当成目标型号报价。其他多 SKU 商品仍有规格对应的不确定性，页面价不是结算承诺。
- 输出仅含“部件、商品名、价格、链接”四列表格，之后是总价和短建议。不再展示联盟披露、运行诊断、重复的技术型号列或公开摘要报价列。
- 表格没有链接或价格的项目保留计划型号并标记未核价；只对实际展示、已选中且通过验证的商品求和。套装同一商品只计一次。缺价时显示小计并明确无法计算总价。
- CPU 与 GPU 的类别不能互相冒充；严格区分型号后缀，主板保留品牌与完整搜索型号。
- 结构化查询记录、替代型号来源与理由、拒绝原因、停止原因和页面诊断仍保存在运行日志，不填满最终回答。
- 表格、价格、链接、总价和内部证据标记由确定性节点生成并校验；输出前移除内部标记，避免 Markdown 渲染显示注释。兼容性描述明确限于已识别参数。

## 迁移与验证

Flow 与内置电脑顾问版本一起升级到 4.7.2；已有 4.7.1 及更早版本的内置会话迁移到新版本，用户选择的商城保留。删除未引用的旧 V3 三轮联盟图；通用联盟节点仍可服务其他 Flow。

回归测试覆盖本次 RX7600 错放 CPU 的回归、网页来源伪造与缺失、完整 Flow 的连续两部件联网降本、预算上下调整、多部件调整、升级超预算保留原方案、缺价不推算预算、全程停止限制、型号价歧义、直链与表格保护，以及旧内置助手迁移。

`apps/client/src-tauri/examples/commerce_parser_probe.rs` 在隐藏的真实 WebView2 中使用本机 HTML 夹具验证 DOM、SSR 和延迟加载。`commerce_session_probe.rs` 用于会话跨进程重启验证。两者都使用独立目录；本机测试不代表线上三个商城的全流程均已成功。
